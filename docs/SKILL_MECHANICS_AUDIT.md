# 技能機制檢查與分段紀錄

本次範圍：回合制 RPG 常見技能效果；沿用現有技能池、狀態製作器與戰鬥公式，不修改既有技能平衡。

## 節點 1：檢查完成

基準：遊戲 chatgpt-dev `1ac21d6`；平衡器 main `8ce110d`。

| 能力 | 現況 | 本次處理 |
| --- | --- | --- |
| 單體／隨機多目標／全體傷害、屬性、暴擊、破甲、吸血 | 已支援 | 保留原公式 |
| 治療、護盾、溢出治療轉護盾 | 已支援；核心治療固定最低血量、護盾固定自身 | 補核心技能目標及溢出設定 |
| DOT／HOT、比例／固定量、真實傷害 | 狀態製作器已支援，直接技能未完整支援 | 共用既有計算基準，補直接技能設定 |
| 增益／減益、冰凍、變形、恐懼、嘲諷、減速、陷阱 | 已支援；控制以敵方為主 | 保留現有控制設計，避免改動戰鬥流程 |
| 普攻觸發、下次技能增傷、行動提前、技能誘發 | 已支援 | 新效果沿用既有發動鏈 |
| 多段攻擊 | 多目標不等於多段，目前缺少每目標多次結算 | 補每目標命中次數，逐段結算、死亡停止 |
| 傷害／治療／護盾附加狀態 | 主效果與 applyStatus 分離 | 補狀態引用與機率，每次施放每目標判定一次 |
| 淨化減益／驅散增益 | 缺少解除入口與明確分類 | 補可解除狀態分類及數量；被動光環不解除 |
| 復活 | 普通治療只作用存活單位 | 補上場陣亡隊友復活與生命比例，不處理候補 |
| 玩家、夥伴、怪物共用效果 | 怪物共用技能已有部分限制 | 新效果同步實作雙方並驗證匯入／匯出 |

檢查路徑：core-game → numeric-compression-formula → mastery → control-status-summon → status-maker → shared-skill-runtime → companions → induction-runtime。設定由平衡器 classes[].skills 經驗證、匯入轉為執行期陣列及 metadata。

## 後續節點

- 節點 2：共用效果與資料驗證、回歸測試，完成後推送遊戲分支。
- 節點 3：平衡器欄位、狀態解除分類、匯入匯出與整合測試，完成後推送兩個分支。

不宣稱涵蓋所有 RPG：位移／碰撞、施法打斷、MP 消耗／回復、任意戰鬥召喚 AI、反擊／傷害反射、任意事件被動與狀態層數仍需要各自獨立設計，不能僅靠新增效果名稱完成。這些不在本次共用效果補齊範圍。

## 節點 2：共用效果完成

- 新增選用 target、hitCount（1～20，每段完整倍率）、powerBasis、damageResolution（standard/fixed/true）、healResolution、drainRate。fixed 不套用防禦／暴擊／屬性但仍由護盾吸收；true 額外穿透護盾。
- 新增 cleanse／dispel／revive；解除數量 1～99，復活比例 0.001～1。復活只處理上場陣亡單位，不重置怪物已發放獎勵。
- 新增 onHitStatusId／onHitStatusChance；主效果成功命中後，每次施放每目標最多判定一次，閃避與死亡目標不附加。
- 狀態新增 polarity（auto/buff/debuff/neutral）及 dispellable（預設 true）。auto 混合正負效果判定 neutral；被動光環、護盾及消耗品不由淨化／驅散解除。
- 核心匯入初始層即保存新 metadata，避免啟動時較早的匯出覆蓋設定；新設定驗證失敗不更動目前資料。
- 玩家、夥伴與怪物沿用原施放資格、技能等級、寶石、精通、冷卻及技能誘發規則。既有未設定新欄位的技能仍委派原執行路徑。

驗證：新效果 runtime／schema 回歸測試及既有夥伴被動測試。平衡器 UI 同步留待節點 3。

## 節點 3：平衡器共用效果完成

- 平衡器嵌入與遊戲完全相同的 skill-effect-schema 與狀態純資料契約；新增目標、段數、計算基準、傷害結算、吸血比例、溢出護盾、淨化／驅散數量、復活比例及附加狀態設定。
- 主角主動／觸發與各夥伴專屬頁共用同一組欄位；既有技能不因打開頁面而寫入新設定，可還原為預設路徑。
- 狀態新增解除分類與允許解除，匯出不丟失；刪除保護納入附加狀態引用。怪物指派允許淨化、驅散與復活。
- 新增設計器契約、匯入匯出、儲存重載及 Chromium 操作測試；實際點擊欄位、下載 JSON、遊戲匯入、引用刪除阻擋、切換效果及夥伴頁均通過。
- 整合檢查另發現平衡器缺少已存在的技能誘發編輯／驗證；留待節點 4 補齊，避免遊戲有功能卻無法設計。
